# 졸업논문 진행 관리 보드

학과별로 다른 졸업논문 절차를 데이터로 정의하고, 학생·교수·행정실이 같은 진행 상태를 보는 Next.js 데모입니다. 모든 학과, 인물, 연락처, 날짜는 가상 예시입니다.

## 실행

```bash
npm ci
npm run dev
```

`http://localhost:3000`에서 시작합니다. 검증은 `npm test`, `npm run build`, `npm run test:e2e` 순서로 실행합니다. E2E는 빌드한 프로덕션 서버를 사용합니다. 최초 실행 전에는 `npx playwright install chromium`이 필요할 수 있습니다. 기존 pnpm 잠금 파일도 보존되어 있지만 재현 기준은 package-lock.json입니다.

## 가정과 시연 데이터

- 승인과 확정은 구분한다. 교수 승인 즉시 신청 상태는 `승인`, 안내는 `행정실 확정 검토 중`으로 표시하며, 해당 전공의 다음 할 일은 검토 결과 대기로 바뀐다. 기존 마감으로 전공 간 우선순위를 비교한다. 행정실이 `검토 완료`로 처리해야 지도교수 확정 단계가 완료되고 해당 전공 로드맵만 다음 단계로 이동한다. `보완 요청`이면 대기 대신 피드백 확인·보완을 안내한다. 이는 AGENTS.md의 두 규칙에 대해 사용자가 명시한 해석이다.
- 논문 요건 누락은 면제와 다르다. 누락된 전공은 임의로 로드맵을 생성하지 않고 전공명·전공 유형과 `정보 확인 필요` 안내를 표시한다.

- 가상 학생은 8명이며, 대표 학생 김하늘은 심리학과 주전공·기계공학과 복수전공 조합입니다.
- 사회학과를 포함한 다전공 학생도 포함합니다. 사회학과 복수전공은 면제라 로드맵이 생성되지 않습니다.
- 사회학과 차현우 교수는 정원 2명 중 2명이 배정된 정원 마감 사례입니다.
- 공식 주소가 제공되지 않아 모든 공식 링크는 `예시 링크(가상)`으로 표기합니다.
- 같은 주는 월요일~일요일(한국 날짜)을 뜻하며, 완료 여부와 무관하게 모든 단계 마감의 전공 간 충돌을 보여줍니다.
- 단일 전공도 시작할 수 있습니다. 전공 탭은 전체 보기를 기본으로 제공하고, 면제 전공은 별도 면제 안내만 표시합니다.
- 행정실 대상·완료 숫자는 필터에 포함되는 고유 학생 수, 미확정·확정 검토 대기·심사 대기는 학생-전공 건수입니다. 전공 입력 전 학생은 seed 명단의 전공으로 집계합니다. 완료 학생은 필터 범위의 모든 필수 단계가 완료된 경우만 셉니다.
- 수업 기반 배정은 수강 확인을 함께 완료하는 것으로 가정하며, 배정 확인 단계까지 완료됩니다. 그 외 단계는 현재 단계의 제출 완료 기록으로 이동합니다. 심사·성적 단계의 기록도 시연용 상태이며 실제 심사 결과가 아닙니다.
- 교수 정원의 seed 배정 인원에는 화면의 8명 외 기존 지도 학생도 포함된 것으로 가정합니다. 새 승인은 정원 사용 학과에만 1회 증가합니다.

## 3분 시연 대본

1. 첫 화면에서 학생 역할을 선택하고, 심리학과 주전공·기계공학과 복수전공을 입력해 로드맵과 통합 마감 경고를 확인합니다.
2. 심리학과 카드에서 `교수 컨택 완료`를 기록하고 승인 요청을 누릅니다. 교수 화면에서 해당 신청의 연구 주제와 계획을 보고 승인합니다.
3. 학생 화면에서 신청 상태 `승인`, `행정실 확정 검토 중` 안내와 바뀐 다음 할 일을 확인합니다. 행정실 검토 전이므로 지도교수 확정 단계는 유지됩니다.
4. 행정실 화면에서 승인 건을 `검토 완료`로 처리하고, 학생 화면에서 심리학과만 다음 단계인 `논문 작성`으로 이동한 것을 확인합니다. 기계공학과 로드맵은 그대로입니다.
5. 사회학과 정원 마감 교수는 신청·승인 버튼이 비활성인 점도 확인합니다.

## 사용자 테스트 질문

- 지금 가장 먼저 해야 할 일은 무엇이고 언제까지인가요?
- 두 전공의 일정이 겹치는지 어디에서 확인할 수 있나요?
- 지도교수 승인 후 왜 행정실 검토가 추가로 필요한지 이해되나요?
- 교수 피드백이나 보완 요청은 학생 화면에서 어디에 보이나요?

## 학과 데이터 교체

`data/departments/`의 학과별 TypeScript 파일만 추가·교체합니다. `Department` 타입의 학과명, 요건, 지도교수 방식, 정원 사용 여부, 모든 단계의 마감일·제출 방법·서식·연락처를 채워야 합니다. 실제 정보가 `docs/departments/*.md`에 제공되면 해당 데이터를 반영합니다. 화면 코드는 학과명이나 단계명을 고정하지 않습니다.

지도교수 확정/배정 단계는 데이터의 예약 ID `advisor`로 정의합니다(표시 이름은 자유). 심사 대기로 집계할 단계에는 `review: true`를 지정합니다. 색상은 `violet`, `sky`, `amber`를 지원하고 그 외는 회색입니다. 새 학과는 index.ts 목록에도 등록하고 교수·학생 합성 데이터의 departmentId를 맞춥니다. 필수 필드 누락은 데이터 완결성 테스트에서 실패해야 합니다.

## 남은 한계

다음은 /goal의 '이번에 하지 않을 일'로 지정한 범위입니다.

- 실제 학과 정보 수집, 실제 인증·로그인, 서버 DB 및 외부 API 연동을 제공하지 않습니다.
- 실제 파일 업로드는 제공하지 않습니다. 서류 종류·문의처를 보여주고 제출 상태·시각만 브라우저에 기록합니다.
- 이메일·알림 발송은 제공하지 않습니다.
- 학과 추가·편집 관리 화면, 행정실의 명단 등록·요건 관리·공지 등록·명단 내보내기는 '준비 중' 메뉴만 제공합니다.
- 상태 공유는 동일 브라우저의 역할 전환을 기준으로 하며 실제 여러 사용자의 서버 동기화는 제공하지 않습니다.

별도 유지보수 사항: 기존 Next.js 15.5.2의 취약 버전 경고는 기능 완료 기준과 별개로 남아 있습니다. 외부 공개 전에 패키지 보안 업데이트가 필요합니다. 이번 작업에서는 배포·push를 수행하지 않습니다.

사람이 수행할 3분 리허설, 1분 내 이해도, 5명 중 4명 정답 검증은 아직 수행하지 않았으며 에이전트 완료 판정에 포함하지 않습니다.
