# 졸업논문 진행 관리 보드

학생·교수·학과 조교가 같은 브라우저에서 진행 상태를 공유하는 데모입니다. 기본 화면은 사용자가 제공한 `codex_revision_spec.md`를, 학과 절차는 추가 제공한 [snu_thesis_procedures_for_service.md](docs/departments/snu-thesis-procedures.md)를 기준으로 합니다. 초기 AGENTS.md 및 docs/student.md·professor.md·admin.md와 충돌하는 역할·승인 규칙은 아래 새 명세 해석을 우선했습니다. 초기 문서는 원문 기록으로 보존했습니다.

## 실행

Node 22/24 LTS와 npm을 사용합니다(로컬 검증: Node 24.21.0, npm 11.19.0).

```sh
npm ci
npm run dev -- --hostname 127.0.0.1 --port 3000
```

접속: http://127.0.0.1:3000. 개발 서버는 이 컴퓨터에서만 접속됩니다. npm/package-lock.json으로 통일했으며 pnpm 설정은 없습니다.

## 역할과 핵심 흐름

### 학생 화면 탐색 및 색상

- 공통 강조색은 [서울대학교 공식 UI 가이드](https://identity.snu.ac.kr/color/1)의 SNU Blue RGB 15, 15, 112 (`#0F0F70`)를 사용합니다. 연한 배경과 hover 색은 앱용 파생색이며, 공식 로고나 공식 서비스 표시는 추가하지 않았습니다.
- 전공 구분색은 유지하고, 학생 업무는 로드맵 / 지도교수 / 면담 일정 / 연구계획·논문 / 캘린더 / 공지 탭으로 나눴습니다.
- 다음 할 일 버튼·알림·캘린더는 대상 전공과 업무 탭을 열어 줍니다. 탭 이동과 새로고침 후에도 초안이 보존됩니다. 학생 업무 탭은 좌우 화살표 및 Home/End 키로 이동할 수 있습니다.
- 이번 수정은 UI 탐색 변경이며 기존 2차 명세의 승인·권한 규칙은 바꾸지 않습니다.

- 학생: 전공별 요약·탭·세로 로드맵, 교수 탐색, 신청과 임시저장, 면담 시간 선택, 연구계획·최종논문 제출 및 재제출.
- 교수: 학년도 정원·모집 상태, 신청 승인/수정/면담/반려, 피드백 수정, 제출물 검토.
- 학과 조교: 절차 초안 편집·게시, 대상 공지, 소속 학생 전원 검색 및 읽기 전용 진행 조회. 지도교수나 교수 정원을 쓰는 기능은 없습니다.

지도교수 결정 방식은 **신청·승인형 / 수업형** 두 가지입니다. 서비스의 신청이 첫 연락이므로 사전 연락 여부를 묻지 않습니다. 교수 승인 즉시 해당 전공의 지도교수 단계가 완료되고 다음 단계로 이동합니다. 조교 확정 검토는 없습니다. 수업형은 학생의 수강 분반 데이터에서 담당 교수를 읽으며 조교가 지정하지 않습니다.

## 시연 순서

1. 학과 조교에서 첫 단계 마감일 수정 → 임시저장 → 학생 화면은 그대로인 것 확인 → 게시 → 학생의 일정 변경 배지·알림 확인.
2. 김서연의 심리학과에서 서진우 교수를 선택하고 신청서를 작성·임시저장 → 새로고침 → PDF/DOCX 첨부 후 제출.
3. 교수에서 피드백과 면담 가능 시간을 선택·전송 → 학생에서 한 시간을 선택 → 양쪽 일정·학생 캘린더 확인.
4. 교수 승인 → 승인 인원 증가 및 학생의 연구계획서 단계 확인. 피드백 수정 → 학생 알림·수정 시각 확인.
5. 학생 연구계획 제출 → 교수 승인 → 교수의 내 지도 학생에서 지도 면담 제안 → 학생 시간 선택 → 교수 면담 완료 → 최종논문 제출 → 교수 수정 요청 → 학생 v2 재제출 → 교수 승인.
6. 박도윤으로 전환해 수강 분반 지도교수와 신청 단계가 없는 로드맵 확인. 수업형 중간점검은 자료 제출 후 교수 확인을 받습니다.
7. 조교 학생 검색에서 초과학기·졸업예정 학기·학번 필터로 이준호를 찾고 읽기 전용 상세 확인.

## 데이터 및 구현 가정

- 학과·단계·마감은 data/departments의 데이터와 조교가 게시한 브라우저 데이터에서 생성합니다. 컴포넌트는 학과명·단계명을 고정하지 않습니다. 단계 종류(kind)가 제출/검토/수강 동작을 결정합니다.
- 조교 초안은 실시간 미리보기와 자동/수동 임시저장을 지원합니다. 학생에게는 게시된 버전만 보입니다. 학기·대상·제출물·제출처·예외사항·필수 여부·첨부 서식이 데이터에 포함됩니다.
- 신청 제출과 교수 승인을 별도 단계로 정의할 수 있습니다. 중간점검 등 교수 검토가 필요한 자료도 plan 종류를 사용합니다. task는 외부 활동을 마친 학생이 완료를 기록하는 데모 단계입니다.
- 한 학과의 활성 게시 절차 1개를 관리합니다. 학기별 절차 아카이브나 실제 학사 시스템 동기화는 없습니다.
- 일정 변경 배지는 게시 후 7일 동안 표시합니다. 시간은 사용하는 브라우저의 현지 시간 기준이며 한국 시간 환경으로 시연합니다.
- 교수의 기존 지도 학생은 baselineAssigned, 추가 승인 학생은 신청 상태로 계산합니다. 같은 신청을 중복 승인해도 인원이 늘지 않습니다. 화면에서 편집하는 학년도는 현재 데모 정원의 학년도입니다.
- 새 시드는 김서연(심리·중어중문), 박도윤(기계공학부·2027년 8월 졸업), 이준호(초과학기), 최민재(산업공학과), 교수 5명, 학과별 조교 4명입니다. 인명·연락처·정원은 모두 가상입니다. 학과 절차는 제공 자료 기반이며 원문에 명시된 상세 공식 링크만 사용합니다.
- 새 데이터는 `thesis-board-v3`, UI 초안은 `thesis-form-v3-*`에 저장합니다. 기존 v2 및 이전 데이터는 삭제하지 않습니다. 새 데이터 구조로 첫 진입하면 새 데모로 시작하며 이전 진행 기록을 자동 변환하지 않습니다. 데모 초기화는 v3 상태와 v3 초안만 초기화합니다.

## 실제 학과 자료 반영 가정 (2026-09-22)

### 대시보드 UI 추가 수정

- 조교의 절차 편집기와 오른쪽 미리보기는 모든 단계를 접고 시작합니다. 왼쪽 요약은 단계명·기간·진행 방식을 표시하고, 필요한 단계만 펼쳐 편집합니다.
- 단계 추가·삭제를 지원합니다. 단계 순서는 고정하며 정렬·드래그·위아래 이동 기능은 없습니다. 새 단계는 마지막에 추가하며, 저장 규칙도 기존 단계의 재정렬과 중간 삽입을 거부합니다.
- 왼쪽 요약은 `2026. 10. 02. 18:00`, 학생용 마감·미리보기는 `10월 2일 18:00까지`로 표시합니다. 날짜 선택 입력기 자체는 브라우저 표준 UI를 유지합니다.
- 교수 기본 탭은 '내 지도 학생'입니다. `?tab=applications` 등 알림에서 명시한 탭은 유지합니다.
- 재사용할 수정용 문장은 [학과 조교 대시보드 프롬프트](docs/assistant-dashboard-prompt.md)에 정리했습니다. 프로젝트 내에 사용자가 인용한 문장을 가진 기존 프롬프트 파일이 없어 새 문서로 추가했습니다.

### 자료 및 처리 해석

- 원문 보존: docs/departments/snu-thesis-procedures.md. 사용자 제공 조사 요약을 반영했으며 최신 공지 원문을 독립 검증한 서비스가 아닙니다. 각 학과에 출처 설명과 일부 가정 배지를 표시합니다.
- 심리학과는 과거 공지 요약 기반으로 최신 일정·상세 공식 링크가 미확인입니다. 산업공학과 주·복수전공 요건은 문서에 없어 필수로 가정하고 학생 화면에 '정보 확인 필요'를 명시합니다.
- 중문·산공은 실제 학과 배정/선임을 서비스의 신청·교수 승인으로 변형했습니다. 조교 배정·확정 검토는 없습니다. 중문의 9/14 배정 공지일은 실제 신청 마감이 아니며 데모에 옮긴 값임을 표시합니다.
- 문서의 CONFIRMED는 제공 자료에서 날짜를 확인했다는 뜻입니다. 문서가 기본값으로 둔 18:00 및 중문 발표 09:00 등은 실제 확인 시각이 아닙니다. 미확인 일정은 PLACEHOLDER/isPlaceholder로 저장하고 조교 화면에서만 '예정값' 배지를 표시합니다. 학생에게도 출처 설명·일정 근거를 제공합니다. 날짜가 없는 면담은 '정보 확인 필요'로 표시합니다.
- 기존 내부 필드 method=application/course, target=primary/secondary/all은 문서의 advisorMode, appliesTo에 대응합니다. stepType이 세부 의미를, kind가 기본 동작을 표현합니다.
- 산공의 계획서 초안·영상은 지도교수 확정 전 '접수됨'으로 기록합니다. 실제 이메일·영상 업로드를 대신하지 않으며 영상은 HTTPS 링크 기록만 지원합니다. PDF/DOCX 제한은 유지합니다.
- 교수의 '내 지도 학생'에서 지도 면담을 제안하고 심사 결과를 입력합니다. 면담은 해당 단계의 교수 완료만 인정합니다. 심사 결과는 해당 학생·전공의 조건부 마감과 캘린더만 좁힙니다. 결과가 없으면 두 마감을 표시합니다.
- 기계공학부는 설계1·2 분반을 모두 받은 가상 수강 데이터로 전체 여정을 시연합니다. 서비스에서 수강신청·분반 선택은 하지 않습니다. 수강 확인은 과목 이수·성적 확정을 의미하지 않습니다. 미확인 최종논문 형식·제출처와 2027년 일정은 가정임을 표시합니다.
- 외부 제출·발표 참석은 학생 자가 기록이며 실제 학사 승인·출석 검증이 아닙니다. 서명 필요 배지는 안내이며 전자서명 검증은 하지 않습니다.
- 다른 전공에 같은 파일 바이트가 제출된 경우 경고를 확인해야 제출할 수 있습니다. 이름 변경에도 검사하지만 표절 판정이나 다른 파일 형식 간 내용 비교는 하지 않습니다. 경고 확인은 실제 이중 제출 허용을 뜻하지 않습니다.
- 서어서문학과·불어불문학과는 원문에서 발표회 참고용이므로 별도 로드맵은 만들지 않았습니다. 선택적 교수 상한(maxStudentsPerAdvisor) 검증은 지원합니다.

E2E는 프로덕션 빌드를 localhost 전용 서버에서 실행합니다. 개발 서버를 종료하고 빌드하세요(.next 공유 충돌 방지). 별도 lint 스크립트는 없으며 빌드의 타입·기본 정적 검사를 수행합니다. 항목별 완료 확인과 반복 수정 결과는 [docs/progress.md](docs/progress.md)에 기록합니다. 이전 보안 감사 이력은 [AUDIT.md](AUDIT.md)를 참고하세요.

## 남은 한계

- DB·백엔드·인증·외부 API가 없는 브라우저 데모입니다. 여러 컴퓨터 간 동기화나 실제 권한 보안은 제공하지 않습니다. 역할별 순수 상태 전이 함수가 허용 동작을 검사하지만 로그인 보안을 대신하지 않습니다.
- 파일은 이 브라우저 localStorage에 저장되며 파일당 512KB, 전체 저장 직렬화 약 3백만 문자로 제한합니다. PDF는 미리보기, PDF/DOCX는 다운로드를 제공합니다. DOCX는 외부 문서 편집기에서 엽니다. 실제 서버 업로드·악성파일 검사·영구 보관은 없습니다.
- 실제 이메일·SMS, 공지 PDF의 AI 구조화, 공식 문서 질의응답은 구현하지 않습니다. 알림은 앱 안에서만 전달됩니다.
- 사람 대상 3초 이해도·사용성 실험은 수행하지 않았습니다. 자동 브라우저 시나리오·375px 가로 넘침 검사와 캡처 점검을 수행합니다.
- 의존성은 이번 기능 수정에서 변경하지 않았습니다. 이전 감사 기준 critical/high 0, moderate 11개 전파 항목이 남습니다(Vitest/mocker와 PostCSS). 상세 미수정 사유는 AUDIT.md에 보존했습니다.
